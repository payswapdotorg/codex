# APP-001 — Launch Surface + User-Facing Workflow Entry Point

**Status:** READY
**Depends on:** none
**Surface:** existing Codex client/TUI/app-server/application-protocol surfaces + smallest required workflow entry integration

## Objective

Produce a verified user-facing Codex Universal launch surface from the current repository without creating a second agent runtime or second workflow engine.

## Required work

1. Audit the current Codex CLI/TUI and app-server/application-protocol/client surfaces.
2. Identify the smallest existing surface that can serve as the first Codex Universal end-user application.
3. Expose the existing workflow/teaching capabilities through that surface through the existing contracts/control plane.
4. Add only the client integration required to reach the real workflow path.
5. Provide a deterministic local launch command from the built artifact.
6. Add a smoke test proving:
   - application starts;
   - user can create/start a session;
   - workflow entry point is visible;
   - a representative workflow action reaches the existing runtime/control plane;
   - shutdown/relaunch does not corrupt supported local state.

## Forbidden

- second agent runtime;
- second workflow engine;
- parallel workflow semantics in the client;
- provider/environment-specific workflow semantics in universal contracts;
- bypassing workflow-control-plane authority;
- inventing a web/mobile product solely because it is convenient;
- implementing marketplace/payment functionality as part of the launch surface.

## Acceptance

A fresh build can launch a clearly identified Codex Universal application surface and reach the real workflow experience without internal API calls standing in for a missing user path.

The completion report must identify the chosen client surface, why it is the smallest correct route, exact build/launch commands, changed files, tests, and known limitations.
