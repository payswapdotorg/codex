# RWO-005 post-hoc: experimental precomputed export regeneration
# Captured: 2026-09-14T21:05Z-21:30Z (UTC)

## why regeneration was needed
Adding the workflow/fork protocol method changes what ts-rs/schemars
generate; the vendored experimental precomputed export
(schema/precomputed/app-server-exports-experimental.json.zst) must contain
the new types or `cargo test -p codex-app-server-protocol`'s
experimental_precomputed_exports_match_generated test fails (RWO-001
established this; see docs/validation/evidence/rwo-001/post-hoc/
experimental-zst-regeneration.txt).

## method (RWO-001 lesson-118 precedent, adapted)
The real generator lives behind cfg(test) in the protocol crate's test
binary, which cannot link under this pod's 4G cgroup (see
build-verification.txt). The artifact was therefore regenerated by a
python replication of the ts-rs 11.1.0 + schemars 0.8.22 output, with the
format rules re-derived from (a) the vendored tree entries themselves and
(b) the actual generator sources in ~/.cargo/registry (ts-rs 11.1.0
src/lib.rs format_docs and src/export.rs import emission were read
directly; schemars semantics confirmed against 15+ existing entries).

  inline in the response file (matching the WorkflowPublish* shape)

  lines become \n\n) — confirmed byte-for-byte against CommandExecParams
