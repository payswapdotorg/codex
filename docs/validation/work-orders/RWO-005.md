# RWO-005 — Fork + Lineage Product Surface (Mounted via RWO-001)

**Status:** PROPOSED (VWO-010 synthesis)
**Priority:** P1 (Family C)
**Closes (canonical):** Family C (VWO-005 F4; partially VWO-009 F6's fork half)
**Depends on:** RWO-001 (needs the mounted control plane to expose the fork port)

## Objective

Let a normal user fork a published workflow and produce a new immutable
release that provably carries lineage: forked-from identity, upstream digest,
attribution — visible and verifiable on the release.

## Findings closed

- VWO-005 F4 (P1): fork surface + lineage data model absent — the mandated
  lifecycle "fork a workflow and produce a new immutable release" cannot be
  performed by a normal person.
- VWO-009 F6 (P3, fork half): no product fork surface (engine coverage exists;
  attacks were engine-side only).

## Reproduction evidence (VWO-010, at main 0f89393)

`docs/validation/evidence/vwo-010/_infra/post-hoc/20260912T104048Z-fork-improvement-trigger-surface-absence.txt`
— probe 1: FlowMart route inventory has no fork path; probe 2: the engine
(forge + distribution `memory.rs` fork path) implements fork/lineage but
nothing user-facing calls it.

## Fix scope (bounded)

- Expose the existing `codex-workflow-forge` / `codex-workflow-distribution`
  fork port through the RWO-001 mount: one protocol method + CLI subcommand
  (`workflow fork <id>@<version> --as <new-id>`), producing a sealed fork
  release.
- Render lineage on release inspection: forked-from version id + digest,
  attribution (this WO renders it; VERIFICATION of attribution content is
  RWO-016, out of scope here).
- Engine semantics: reuse the existing port as-is. No new fork semantics.
- FlowMart-side fork fixture is OPTIONAL and out of scope unless the Tech Lead
  wants the marketplace lifecycle human-testable pre-mount (then dispatch with
  RWO-010's harness batch as a rider).

## Acceptance criteria

1. A user forks a published version through the product surface; the fork
   appears as a NEW immutable release with the upstream pinned in its lineage
   record; re-publishing the same identity is refused.
2. Lineage is visible in the release listing/detail (forked-from id, upstream
   digest, carried attribution).
3. Empty attribution on a fork is refused (engine already enforces this —
   "a forked release must carry upstream attribution").

## Rollback

Additive mount (one method + one subcommand + rendering). Revert the commit;
no state migration (fork releases are new immutable records).
