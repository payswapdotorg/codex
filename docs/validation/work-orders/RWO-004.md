# RWO-004 — PressRoom: Server-Side Publication Terminality and Publish Version Guard

**Status:** PROPOSED (VWO-010 synthesis)
**Priority:** P1 (Family F — security/trust boundary)
**Closes (canonical):** Family F (VWO-008 F3)
**Depends on:** none

## Objective

Enforce publication terminality and re-review at the server op layer, not only
in the browser UI: a PUBLISHED story body must be immutable outside the
correction gate, and publish must not ship un-reviewed post-approval edits.

## Findings closed

- VWO-008 F3 (P1): (1) `editStory` performs no story-status guard — an
  authorized author mutates a PUBLISHED story via the API twin;
  (2) `publishStory` carries no `expectedVersion` — writer edits landing
  between editor approval and publication go live without re-review.

## Reproduction evidence (VWO-010, at main 0f89393)

`docs/validation/evidence/vwo-010/media-editorial-publishing/post-hoc/20260912T103919Z-vwo008-f3-publication-terminality.txt`
— attack 1: author edited the published st-0206 ("saved as v3") outside the
correction gate; attack 2: post-approval sneaked edit went live
("SNEAKED POST-APPROVAL EDIT — never re-reviewed."); UI oracle: the edit form
is absent for the author on a published story (guard is UI-only).

## Fix scope (bounded)

`docs/validation/fixtures/media/ops.js`:

1. `editStory` (line ~46): after the permission check, add a status gate —
   editing is allowed only for `draft`/`in_review`/`approved` (not
   `published`/`corrected`); rejection: HTTP 409 `terminal_state` pointing to
   the correction path ("use a correction instead", same wording as the
   duplicate-publish path).
2. `publishStory` (line ~159): call `checkVersion(ctx, story)` (the helper
   already exists, line 14) and REQUIRE `expectedVersion` on publish —
   HTTP 400 `expected_version_required` when absent. Editor UI/publish form
   must pass the version it approved; the catalog's publish step gains the
   expectedVersion parameter (RWO-010 aligns the catalog wording).

## Acceptance criteria

1. Author edit on a published/corrected story via API twin → 409
   `terminal_state`, no `story.edited` event, version unchanged.
2. Publish without `expectedVersion` → 400 `expected_version_required`.
3. Publish with a stale `expectedVersion` (story edited after approval) →
   409 `data_conflict` ("reload and re-review"); with the current version →
   ok (happy path unchanged).
4. Correction path (editor) unchanged.
