# RWO-006 — Improvement-Candidate + Approval-Before-Publish Surface (Mounted via RWO-001)

**Status:** PROPOSED (VWO-010 synthesis)
**Priority:** P1 (Family D)
**Closes (canonical):** Family D (VWO-005 F5)
**Depends on:** RWO-001 (needs the mounted control plane to expose the evolution port)

## Objective

Let a normal user produce an improvement candidate from execution evidence and
publish it ONLY after validation and explicit approval — the governed
improvement lifecycle VWO-005 was mandated to exercise.

## Findings closed

- VWO-005 F5 (P1): improvement-candidate-from-evidence and
  approval-before-publish surfaces are absent product-wide (the
  `codex-workflow-evolution` crate implements candidate/approval but has zero
  dependents and no mount).

## Reproduction evidence (VWO-010, at main 0f89393)

`docs/validation/evidence/vwo-010/_infra/post-hoc/20260912T104048Z-fork-improvement-trigger-surface-absence.txt`
— probe 3: no crate in the workspace depends on `codex-workflow-evolution`
(library-only, zero consumers); FlowMart route inventory has no
improvement-proposal path.

## Fix scope (bounded)

- Expose the existing `codex-workflow-evolution` port through the RWO-001
  mount: candidate proposal (from recorded execution evidence), validation
  step, explicit approval gate, then publish-via-existing-review-path.
- Requires the mount to surface execution evidence records (VWO-006 F-4's
  monitoring surface is the natural source; minimal version: evidence
  summary attached to the candidate).
- Engine semantics: reuse the existing evolution port as-is.

## Acceptance criteria

1. A user with evidence visible can propose an improvement candidate through
   the product surface; the candidate cites the evidence.
2. Publishing without approval is refused (the approval gate is a real
   product surface step, not a doc note).
3. After approval + review, the improvement lands as a new immutable version.
