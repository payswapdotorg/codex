# VWO-003 — Validation Harness, Scenario Catalog, and Evidence

**Status:** BLOCKED
**Depends on:** none
**Wave:** 0
**Concurrency:** parallel with VWO-001, VWO-002

## Objective

Create repository-native scenario definitions, evidence schemas, reporting conventions, and reusable validation helpers so all workers produce comparable evidence without bypassing product surfaces.

## Required outcomes

- Canonical scenario catalog covering construction, software, ride-share, media, marketplace, and adversarial scenarios.
- Canonical teaching-mode matrix for DEMONSTRATE, INSTRUCT, HYBRID.
- Worker report schema with exact repository/environment SHA identity.
- Evidence directory layout under `docs/validation/evidence/` and reports under `docs/validation/reports/`.
- Optional lightweight helpers/scripts for workspace setup, scenario reset, timestamped evidence, and report validation.
- Explicit distinction between user-path evidence and post-hoc diagnostic evidence.
- Severity vocabulary P0/P1/P2/P3.

## Forbidden

- Treating the harness as a workflow runtime.
- Replacing human-path testing with direct internal API calls.
- Storing credentials or secrets in evidence.
- Mutating production semantic contracts merely to make tests pass.

## Acceptance

A new worker can select a scenario, understand its user persona/goal/teaching mode, record exact steps and outcomes, attach diagnostics safely, and produce a report that the Tech Lead can compare across workers.

## Verification

Validate the scenario catalog against the accompanying human-workflow validation prompt and commit the schema/examples plus `docs/validation/reports/VWO-003-report.md`.
