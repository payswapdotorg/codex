# VWO-001 — E2B Desktop Resource Proving Ground

**Status:** BLOCKED
**Depends on:** none
**Wave:** 0
**Concurrency:** parallel with VWO-002, VWO-003

## Objective

Provision and validate up to three isolated desktop-capable E2B workspaces using the connected E2B/Composio integration when available, and establish a reproducible fallback environment when it is not.

## Required outcomes

- Discover available E2B sandbox/template capabilities through the connected integration.
- Prefer the desktop-capable template.
- Create isolated workspaces for validation workers.
- Clone the current repository at an exact verified SHA.
- Build/launch the actual Codex Universal runtime/application available in the repository.
- Verify Browser Use, Computer Use, terminal, API/tool/MCP and human-gate paths that the environment can support.
- Capture workspace/template identity without recording credentials.
- Provide deterministic setup/reset instructions for workers.
- Explicitly record any desktop capability unavailable in the connected E2B account.

## Forbidden

- Putting E2B identifiers, credentials, tokens, or secrets into workflow semantics or source.
- Making E2B a workflow semantic dependency.
- Creating provider-specific workflow concepts.
- Replacing Codex Universal with a different orchestration runtime.

## Acceptance

A worker can enter an isolated desktop proving ground, launch the current Codex Universal application/runtime, interact with browser and desktop capabilities, and reproduce the setup from repository instructions. Failure to provision E2B must produce an explicit fallback record rather than silently claiming full fidelity.

## Verification

Record exact repository SHA, template/workspace identities, launch commands, capability checks, reset procedure, and limitations in `docs/validation/reports/VWO-001-report.md`.
