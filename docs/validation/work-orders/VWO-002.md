# VWO-002 — Synthetic Enterprise Application Ecosystem

**Status:** BLOCKED
**Depends on:** none
**Wave:** 0
**Concurrency:** parallel with VWO-001, VWO-003

## Objective

Build a realistic, disposable enterprise application ecosystem that workers can operate through GUI, browser, file, terminal, API/tool, and human approval paths without depending on unstable third-party SaaS.

## Required application families

Construction: projects/tasks, site progress/photos, contractors, budgets/procurement, invoices, safety, documents, notifications.

Software/Google-like: Git forge, issue tracker, CI dashboard, deployment console, incident console, service dashboard, internal docs, ownership directory.

Ride-share: driver onboarding, support, operations dashboard, trips/regions, maps, payments/earnings, incidents, communications.

Media: CMS/editorial, asset repository, image/video workflow, approvals, publication/distribution, corrections, social distribution.

Marketplace: catalog/search, workflow listing, installation/configuration, entitlements/licenses, upgrades, rollback, attribution/provenance.

## Required properties

- Real state, not static screenshots.
- Browser-accessible interfaces.
- At least one desktop-capable application surface where useful.
- APIs/events corresponding to important UI operations.
- Seeded users, roles, permissions and representative data.
- Deterministic failure switches: unavailable service, failed notification, missing asset, denied permission, conflicting data, duplicate event, stale entitlement.
- Reset/seed capability between scenarios.
- No production credentials or sensitive real-world data.

## Forbidden

- Encoding workflow semantics into the application fixtures.
- Creating a second workflow engine.
- Hard-coding the validation suite to one UI automation library.
- Using static mocks where realistic stateful behavior can be provided cheaply.

## Acceptance

Each application family supports at least one complete workflow through a normal human interaction path and one failure path. Workers can use the applications without modifying Codex Universal internals.

## Verification

Provide setup/reset instructions, application inventory, users/roles, seed data, failure controls, endpoints, and `docs/validation/reports/VWO-002-report.md`.
