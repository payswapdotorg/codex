# VWO-006 — Workflow Consumer and Automation Operator Validation

**Status:** MERGED
**Depends on:** VWO-001, VWO-002, VWO-003
**Wave:** 1
**Worker persona:** workflow consumer / automation operator

## Objective

Exercise discovery, compatibility inspection, installation, resource binding, authorization, scheduling, event triggers, execution, monitoring, upgrade and rollback as a normal workflow consumer.

## Mandatory scenarios

- Discover and compare marketplace workflows.
- Inspect capabilities/resources/compatibility before installation.
- Install using explicit resource/account bindings.
- Schedule a workflow.
- Trigger one by webhook/event.
- Rebind an authorized resource without mutating semantic source.
- Observe execution and recovery.
- Upgrade to a new immutable release.
- Reproduce a failed upgrade and rollback explicitly.
- Reconfigure and uninstall/reinstall where supported.

At least one scenario must use INSTRUCT, one DEMONSTRATE and one HYBRID across the worker's test set.

## Acceptance

A non-creator user can discover, understand, install, authorize, execute, recover, upgrade and rollback a workflow without needing repository internals. Version identity stays pinned and resource rebinding never mutates workflow semantics.

## Verification

Record exact identities, authorization decisions, trigger/schedule evidence, recovery outcomes, UX friction and limitations in `docs/validation/reports/VWO-006-report.md`.
