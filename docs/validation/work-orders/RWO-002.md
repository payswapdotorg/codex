# RWO-002 — FlowMart Configure Op: Parse Form JSON + Reject Identity-Impersonating Keys

**Status:** PROPOSED (VWO-010 synthesis)
**Priority:** P1 (Family B) + P2/P3 rider (Family L)
**Closes (canonical):** Family B (VWO-005 F2 · VWO-006 F-2) and Family L (VWO-009 F2 · VWO-006 F-6)
**Depends on:** none

## Objective

Make the FlowMart install-configuration human path actually persist input, and
stop the same op from persisting identity-impersonating config keys.

## Findings closed

- VWO-005 F2 (P1): the `/installs` "Config keys to merge (JSON)" textarea
  POSTs urlencoded; `configureInstall` receives a STRING, requires
  `typeof object`, silently substitutes `{}` — success flash "configured (no
  keys)", unchanged config cell, misleading history/event entry.
- VWO-006 F-2 (P1): same defect; also blocks the mandated
  adv-environment-failure-rebinding human path (rebind goes through configure).
- VWO-009 F2 (P2): `configure` accepts `version`/`digest`/`targetVersion`/
  `manifest` keys into the install config record (inert data, but rendered).
- VWO-006 F-6 (P3): unvalidated binding-key namespace accepts
  semantic-shadowing keys.

## Fix scope (bounded)

`docs/validation/fixtures/marketplace/ops-install.js` `configureInstall`
(and the install op's config intake, same pattern):

1. `JSON.parse` string values for the `config` field; on parse failure return
   HTTP 400 `invalid_json` naming the field — NEVER a silent `{}` success.
2. Reserved-key deny-list: reject (HTTP 400 `reserved_config_key`) the keys
   `version`, `digest`, `targetVersion`, `manifest`, `packageId`,
   `expectedVersion` and any key starting `__`.
3. Update `FAILURES.md` / fixtures README to document the contract.

## Acceptance criteria

1. Browser path: paste `{"opsChannel":"east"}` → Apply config → flash names
   the key; Config cell shows it; history entry lists the key.
2. Invalid JSON in the textarea → explicit error, no "configured" history
   entry, no event.
3. `{"version":"9.9.9"}` → HTTP 400 reserved_config_key; config unchanged.
4. API twin (object JSON) still works — no regression.
