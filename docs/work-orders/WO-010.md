# WO-010 — Workflow Application Integration and End-to-End Runtime

**Status:** BLOCKED
**Depends on:** WO-006, WO-007, WO-008, WO-009
**Surface:** application/workflow integration, runtime orchestration wiring, end-to-end workflow paths

## Objective

Integrate the workflow control, teaching/compiler, Git lifecycle, and multi-environment execution planes into the existing Codex application without creating a parallel agent runtime or workflow engine.

## Required outcomes

- Expose workflow lifecycle through the existing Codex application/app-server surfaces where appropriate.
- Connect immutable workflow versions to durable workflow instances and execution runs.
- Support end-to-end mixed-environment runs, including Browser Use and Computer Use where available.
- Propagate capability/resource readiness, approvals, evidence, recovery, and failure diagnostics through the existing runtime boundaries.
- Preserve ordinary Codex coding-agent behavior when no workflow is being used.
- Add end-to-end integration tests covering create/validate/publish/install/run/recover paths.

## Forbidden

- A second orchestration runtime.
- UI-owned durable workflow state.
- Bypassing existing approvals, sandboxing, policy, sessions, or tracing.
- Silent workflow-version mutation.

## Acceptance

An immutable workflow can be selected, instantiated, executed across multiple environment classes, observed, recovered/escalated, and verified end to end through the Codex application while ordinary Codex behavior remains compatible.

## Evidence

Report end-to-end scenarios, failure/recovery cases, approval/security coverage, upstream regression results, and exact verified SHA.
