# WO-011 — Scheduling, Triggers, Sharing, and Installation

**Status:** MERGED (PR #13, 9bd959d3b)
**Depends on:** WO-010
**Surface:** workflow schedules, event triggers, package discovery, installation/configuration, resource rebinding

## Objective

Make immutable workflows operationally reusable: discoverable, installable, configurable, triggerable, and schedulable through the Codex workflow surface.

## Required outcomes

- Support `USER`, `SCHEDULE`, `WEBHOOK`, `CONNECTOR_EVENT`, `BROWSER_EVENT`, `COMPUTER_EVENT`, `WORKFLOW_EVENT`, and `HUMAN_EVENT` trigger classes.
- Evaluate capability/resource/policy readiness before execution.
- Make trigger handling idempotent and durable through the workflow control plane.
- Install immutable workflow versions with explicit dependency and resource binding.
- Support resource/account rebinding without changing workflow semantic source.
- Reuse existing connector/plugin/skill discovery and authorization mechanisms where appropriate.

## Forbidden

- Events directly mutating workflow meaning.
- Credentials embedded in installed workflow source.
- Silent dependency or version upgrades.
- A second scheduler/control plane unrelated to workflow authority.

## Acceptance

A published workflow can be discovered, installed, bound to authorized resources, scheduled or event-triggered idempotently, and resumed/retried without changing its immutable definition.

## Evidence

Include trigger idempotency, scheduling eligibility, install/bind diagnostics, authorization checks, version integrity, and exact SHA.
