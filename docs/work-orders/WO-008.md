# WO-008 — Workflow Teaching and Compiler

**Status:** READY
**Depends on:** WO-003, WO-005
**Surface:** teaching sessions, trajectory/evidence capture, workflow candidate generation, semantic compiler

## Objective

Turn instruction, demonstration, or hybrid interaction into validated immutable workflow definitions using the frozen semantic and execution contracts.

## Required outcomes

- Support `DEMONSTRATE`, `INSTRUCT`, and `HYBRID` teaching modes.
- Capture bounded trajectory and evidence references using existing Codex session/trace primitives where applicable.
- Generate a `WorkflowCandidate` and compile it to `WorkflowIR` / `WorkflowDefinition`.
- Perform semantic validation, capability/resource/dependency inference, execution-binding proposals, and replay/simulation checks.
- Require approval before publishing a new immutable `WorkflowVersion`.
- Permit deterministic optimization of an observed step only when semantic equivalence, policy, evidence, and resource constraints are satisfied.

## Must inspect

- WO-003 workflow semantic contracts
- WO-005 execution/capability/resource contracts
- existing Codex sessions, traces, skills, tools, planning, and agent primitives

## Forbidden

- Making transcripts/chat history the workflow semantic authority.
- Silent publication or mutation of an existing version.
- Provider/environment-specific workflow semantics.
- A second agent or workflow runtime.

## Acceptance

A user can teach a workflow by instruction, demonstration, or both; the system produces a validated environment-neutral candidate with explicit dependencies/bindings and publishes only an immutable approved version.

## Evidence

Include teaching-mode coverage, compiler validation cases, dependency/binding inference, replay/simulation results, publication immutability checks, and exact SHA.
