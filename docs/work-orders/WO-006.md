# WO-006 — Codex Browser Use Workflow Adapter

**Status:** READY
**Depends on:** WO-005
**Surface:** Codex-native Browser Use bridge and browser workflow adapter

## Objective

Bind workflow execution to the existing Codex Browser Use capability without creating a parallel browser-agent implementation.

## Required outcomes

- Discover and reuse the current Codex Browser Use feature/skill/runtime path.
- Provide capability lifecycle: declared → available → ready → authorized → bound → executing.
- Normalize browser observation/action/result/recovery artifacts into the workflow execution contract.
- Support browser profiles, sessions, tabs, origin scope, takeover, evidence, and recovery.
- Detect missing bridge/runtime provisioning explicitly and return actionable diagnostics.
- Prefer lazy initialization; do not block unrelated workflows or chat startup on browser capability provisioning.
- Support compatible fallback browser adapters only when semantic/policy requirements remain satisfied and record the fallback.

## Forbidden

- Reimplementing a second browser-use agent loop.
- Browser-specific assumptions in workflow semantic types.
- Credential exposure.
- UI-only browser state as workflow authority.

## Acceptance

A published workflow with browser requirements executes using Codex Browser Use when available, records exact capability/binding/evidence identity, handles unavailable readiness explicitly, and can recover/take over without mutating workflow semantics.
