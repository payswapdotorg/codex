# WO-012 — Workflow Distribution, Marketplace, and Monetization

**Status:** MERGED (PR #17, 3f6f2b3f)
**Depends on:** WO-010, WO-011
**Surface:** workflow publication/distribution, licensing, commercial entitlement metadata, marketplace discovery

## Objective

Allow authors to distribute immutable workflow releases privately or publicly and attach commercial policy without coupling payment semantics to executable workflow meaning.

## Required outcomes

- Support private, shared, public, forked, installed, and published workflow states.
- Define attribution, ownership, licensing, provenance, compatibility, and upgrade policy metadata.
- Support paid releases/subscriptions/licensing through a separate commercial entitlement boundary.
- Reuse Codex plugin-sharing/distribution patterns where useful while keeping workflow semantics distinct.
- Ensure installed/executed workflow identity remains bound to an immutable release.

## Forbidden

- Payment credentials in workflow source or ordinary evidence.
- Monetization logic inside the workflow execution engine.
- Silent mutation of published versions.
- GitHub-specific semantics in the universal commercial/workflow contract.

## Acceptance

An author can publish an immutable workflow release, distribute/install it under an access or license policy, and associate commercial entitlements without modifying executable semantics or exposing credentials.

## Evidence

Include release immutability, attribution/provenance, licensing, entitlement isolation, install behavior, and exact verified SHA.
