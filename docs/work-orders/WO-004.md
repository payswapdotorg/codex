# WO-004 — Provider Portability

**Status:** BLOCKED
**Depends on:** WO-002
**Surface:** provider adapters, model capability tests, provider configuration/routing integration

## Objective

Implement model-provider portability behind the frozen universal Model Plane while preserving default OpenAI behavior.

## Required outcomes

- Implement/complete provider adapters against the WO-002 universal contracts.
- Preserve existing OpenAI request, streaming, cancellation, retry, authentication, and session behavior unless explicitly normalized by WO-002.
- Add capability-aware provider/model selection and explicit unsupported-capability diagnostics.
- Demonstrate that equivalent runtime requests can switch providers without rewriting durable thread/workflow semantics.
- Keep provider SDK/types/configuration behind adapter boundaries.

## Must inspect

- `codex-rs/model-provider`
- `codex-rs/model-provider-info`
- model/auth/session/request/response surfaces identified by WO-002
- existing model selection/configuration and tests

## Forbidden

- Workflow implementation.
- Browser/computer integration.
- Provider-specific fields in universal workflow contracts.
- Unrelated provider behavior changes.

## Acceptance

At least two provider paths can satisfy the same universal request contract where their capabilities permit; unsupported features fail explicitly; durable runtime semantics remain provider-neutral; OpenAI compatibility tests remain green.

## Evidence

Report exact provider adapters changed, capability matrix, compatibility tests, unsupported-feature cases, and verified SHA.
