# WO-002 — Universal Model Contract

**Status:** MERGED (PR #3, 412ec519)
**Depends on:** WO-001
**Surface:** `codex-rs/model-provider-info`, `codex-rs/model-provider`, new universal model contract crate if required

## Objective

Extract and freeze the provider-neutral model contract so OpenAI is one adapter and other LLM providers can be swapped without changing durable Codex thread/workflow state.

## Required outcomes

- Audit every provider-specific assumption on the runtime request/response path.
- Define `ModelProvider`, `ModelDescriptor`, `ModelCapabilities`, `ModelRequest`, `ModelResponse`, `ModelEvent`, `ModelError`, and `ModelSession` boundaries.
- Preserve OpenAI behavior by default.
- Add capability negotiation and diagnostics for unsupported model features.
- Normalize streaming, cancellation, retry/transport, authentication, and session lifecycle without leaking provider protocol types.
- Keep model/provider configuration out of durable workflow semantics.

## Must inspect before coding

- `codex-rs/model-provider`
- `codex-rs/model-provider-info`
- model selection/configuration and model endpoint surfaces
- request/response/streaming/auth/session/cancellation/retry call paths
- thread/session persistence or protocol fields containing provider/model identities
- relevant protocol/app-server boundaries and tests

Do not infer provider boundaries from crate names alone; trace the actual runtime request path.

## Forbidden

- Workflow implementation.
- Browser/computer integration.
- Provider behavior changes unrelated to isolation.
- New UI.
- Provider SDK types crossing the universal boundary.

## Acceptance

The same durable thread can be configured for two providers without changing workflow/thread semantic state; unsupported capabilities fail explicitly; provider-specific request/response/configuration types do not cross the universal boundary; default OpenAI behavior remains compatible.

## Evidence

Report the provider-specific assumptions audited, final universal types/boundaries, capability matrix, compatibility tests, unsupported-capability tests, and exact verified SHA.
