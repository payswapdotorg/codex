# WO-005 — Multi-Environment Execution Contract

**Status:** BLOCKED
**Depends on:** WO-003
**Surface:** new workflow execution/capability/resource contracts and adapters boundary

## Objective

Create one execution abstraction capable of routing workflow steps across Codex-native and external environments without duplicating the workflow engine.

## Required outcomes

- Define `ExecutionEnvironment`, `EnvironmentAdapter`, `CapabilityBinding`, `ResourceBinding`, `Observation`, `Action`, `ActionResult`, `Recovery`, and takeover contracts.
- Model `BROWSER`, `COMPUTER`, `TERMINAL`, `API`, `TOOL`, `MCP`, and `HUMAN` as peer environments.
- Reserve `MOBILE`, `REMOTE_DESKTOP`, and future environments without semantic changes.
- Support mixed-environment workflows within one graph/run.
- Make required capability/environment availability diagnosable and policy-controlled.
- Reuse Codex approvals, sandboxing, skills, plugins, MCP, sessions, traces, and agent primitives where applicable.

## Forbidden

- Implementing browser or computer runtime internals in this Work Order.
- Creating a second workflow engine.
- Hard-coding GitHub or a model provider.

## Acceptance

The same workflow step semantics can bind to different compatible environments; one execution can contain multiple environments; unavailable required capabilities fail explicitly; no environment adapter becomes semantic authority.
